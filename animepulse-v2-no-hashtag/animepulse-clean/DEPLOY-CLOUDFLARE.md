# AnimePulse — Cloudflare Workers deployment

AnimePulse is a dynamic Next.js application: it has route handlers, authenticated admin actions, and an AutoPilot schedule. Deploy it as a **Cloudflare Worker**, not Cloudflare Pages.

## Git deployment settings

In **Cloudflare Dashboard → Workers & Pages → Create → Import a repository**, select this repository and set the project root to:

```
animepulse-v2-no-hashtag/animepulse-clean
```

Use these commands:

| Setting | Value |
| --- | --- |
| Build command | `npm run build:cloudflare` |
| Deploy command | `npm run deploy` |
| Build output directory | _Leave empty — Workers uses `.open-next` internally_ |

Do not configure this project as Pages and do not use `.vercel/output/static`; this directory is not generated by Next.js.

## Required bindings and secrets

`wrangler.toml` already declares the `ANIMEPULSE_KV` namespace. Create the same binding in the Cloudflare dashboard if it does not already exist.

Add these Worker secrets:

```bash
npx wrangler secret put CRON_SECRET
npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put FIREBASE_SERVICE_ACCOUNT_KEY
# Optional
npx wrangler secret put DISCORD_WEBHOOK_URL
```

Add public environment variables in the Worker dashboard: `NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`, `NEXT_PUBLIC_FIREBASE_PROJECT_ID`, `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`, `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`, `NEXT_PUBLIC_FIREBASE_APP_ID`, and `NEXT_PUBLIC_APP_URL`.

## Local commands

```bash
npm install
npm run build:cloudflare
npm run preview
npm run deploy
```

`custom-worker.ts` deliberately wraps OpenNext's generated handler, preserving the existing scheduled AutoPilot Worker while serving all Next.js pages and API routes.
